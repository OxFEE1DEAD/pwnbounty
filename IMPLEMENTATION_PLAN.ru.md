Дата: 30 октября 2026. Цель и сроки: [план на победу](WIN_PLAN.ru.md). Все пути ниже — предлагаемые, кроме существующих `contract/src/{lib,interface}.rs` и `verifier/src/{interfaces,verifier}.ts`. Этот документ планирует работу; чекбоксы не обозначают уже реализованные возможности.

Готово: одинаковые сообщения дают одинаковые хеши в Rust и TypeScript; изменение любого значимого поля ломает проверку.

## 2. Агент, инструменты и проверка нарушения

- [ ] `verifier/src/target/config.ts`: фиксировать модель, prompt, инструменты, политику и начальный баланс до финансирования программы.
- [ ] `verifier/src/target/ledger.ts`: изолированный ledger с журналом реально выполненных операций и сбросом состояния на каждый запуск.
- [ ] `verifier/src/target/agent.ts`: цикл модели с ограничением числа шагов и времени; разрешённый атакующий вход — содержимое инвойса.
- [ ] `verifier/src/target/tools.ts`: типизированные платёжные действия; модель не получает доступ к checker, ключам verdict и состоянию escrow.
- [ ] `verifier/src/checker.ts`: проверять изменение ledger относительно закреплённой политики. Текст ответа модели, загруженный transcript и просьба одобрить отчёт не являются доказательствами.
- [ ] `fixtures/targets/`: уязвимая конфигурация и исправленная версия с принудительной проверкой политики перед действием. Обе версии отдельно закреплены.
- [ ] `fixtures/cases/`: запрещённый получатель, нормальный инвойс, выдуманный transcript, попытка повлиять на checker, таймаут, повтор.
- [ ] Разделить результаты: нарушение, отсутствие нарушения, ошибка инфраструктуры. Ошибка модели или TEE не считается доказательством безопасности и не расходует награду.

Готово: атака приводит к запрещённому действию в уязвимом варианте; исправленный вариант блокирует действие; сохраняются результаты повторных запусков без обещания детерминированной модели.

## 3. Шифрование, TEE и модель

- [ ] `verifier/src/crypto.ts`: завершить шифрование/расшифровку, версионирование envelope, привязку контекста через authenticated data, обработку неверного ключа и изменённого ciphertext. Проверить существующий `seal` перед использованием.
- [ ] `verifier/src/enclave/local.ts`: закончить локальный адаптер; явно пометить его как непригодный для доверенных выплат.
- [ ] `verifier/src/model/near-ai.ts`: проверить API key без вывода значения, доступность модели и инструментов; внедрить лимиты и обработку ошибок.
- [ ] `verifier/src/attestation/`: проверять свежесть evidence, цепочку доверия, допустимый код, привязку signing/encryption keys и модельную границу конфиденциальности. Отказ при неполной проверке.
- [x] Выбрать реальный TEE-адаптер после проверки runtime OutLayer. Выбран OutLayer, Rust `wasm32-wasip2` (31.10: runtime только WASM, attestation прогона проверена).
- [ ] Модель для агента — только TEE-аттестованная: `Qwen/Qwen3.8-27B` (tool calling проверен) или `Qwen/Qwen3.6-35B-A3B-FP8`.
- [ ] `deploy/runner/`: воспроизводимая сборка и digest, ограничение исходящих соединений, ресурсов, секретов и журналирования. Код атакуемого агента изолирован от доверенного checker.
- [ ] Зафиксировать механизм доверия контракта к signer: проверяемая аттестация или проверяемый результат утверждённого attestation verifier. Простая регистрация ключа администратором не закрывает задачу.
- [ ] Проверить приватность полного пути до модели; не использовать обычный API как скрытый запасной маршрут.

Готово: зашифрованный запрос проходит реальную аттестованную среду, а подмена кода, ключа или evidence отвергается. Доступ к провайдеру — внешняя зависимость этой стадии.

## 4. Контракт и гарантированная награда

- [ ] Разделить `contract/src/lib.rs` на модули `bounty.rs`, `claims.rs`, `settlement.rs`, `verification.rs`, `events.rs`; публичные структуры держать в `interface.rs` или `types.rs`.
- [ ] Закрепить за каждой программой правила, конфигурацию, ключ команды и политику verifier. Убрать возможность глобальной заменой signer изменить уже профинансированные программы.
- [ ] Первая версия: одна полная награда за программу. Требовать достаточное финансирование, учитывать storage отдельно от награды, исключить частичную выплату через `min(pool, reward)`.
- [ ] Определить порядок допустимых заявок, предел очереди, срок обработки и освобождение резерва. Ограничить возможность удерживать награду спамом; описать последствия недоступности runner.
- [ ] `commit`: привязать заявку к охотнику и программе, оплачивать занимаемое хранилище; не использовать один глобальный hash как единственную идентичность заявки.
- [ ] `settle`: проверять подпись и весь контекст verdict, сроки, состояние заявки, существование доступного резерва и однократность награды.
- [ ] Реализовать состояния выплаты `Pending → Paid` либо `Retryable`; приватный callback проверяет результат promise. Повтор выплаты не может дважды списать награду.
- [ ] `withdraw`: возвращать только свободные средства после завершения предусмотренных сроков; pending claims и выплаты сохраняют резерв. Обрабатывать неудавшийся возврат.
- [ ] Определить финализацию deployment: проверка отсутствия полномочий sponsor/admin обновить код или сменить доверие после финансирования. Любые необратимые действия выполнять отдельным шагом развёртывания.
- [ ] Структурированные события и views: состояние программы, резерв, заявка, фактический результат выплаты, ссылка/хеш disclosure.
- [ ] `contract/tests/`: скопированный commitment, подмена hunter/сети/контракта/правил, replay, двойная выплата, expiry, withdraw при pending, failed transfer, спам и неверная подпись.

Готово: полная награда подтверждается receipt и балансом; sponsor не может забрать зарезервированные средства; повторные и ошибочные действия не нарушают учёт.

## 5. Сквозной сервис и раскрытие

- [ ] `verifier/src/verifier.ts`: оркестрация загрузки закреплённого конфига, расшифровки, проверки commitment, запуска агента, checker, шифрования отчёта и подписи verdict.
- [ ] `verifier/src/disclosure.ts`: сохранять ciphertext с проверкой целостности и доступности до settlement; определить срок хранения и восстановление после сбоя.
- [ ] `verifier/src/settler.ts`: отправка verdict в контракт, ожидание receipts, безопасные повторы и восстановление после перезапуска.
- [ ] `verifier/src/jobs.ts`: устойчивые состояния задания, идемпотентность, таймауты, квоты и лимиты затрат. Не хранить plaintext атаки в обычной очереди.
- [ ] `scripts/demo.ts`: create/fund → commit → encrypted submit → execution → settle → подтверждение баланса → расшифровка командой.
- [ ] Выполнить на testnet основной и отрицательный сценарии; сохранить публичные evidence без секретов. Локальная подпись не заменяет реальный TEE в итоговом доказательстве.
