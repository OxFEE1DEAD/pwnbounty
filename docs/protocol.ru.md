# Протокол v1 — текущая реализация

## Область доверия

Локальная реализация не обеспечивает TEE-конфиденциальность. `NearAiDevelopmentModel` использует HTTPS без проверки аттестации. `LocalDevelopmentTrust` разрешён только для разработки. `RejectUnverifiedTrust` запрещает запуск до подключения реального verifier evidence. Контракт закрепляет предоставленный signer, но пока не проверяет происхождение ключа из TEE. Full-access ключ аккаунта deployment также пока не удалён.

## Идентичность и подпись

Идентификаторы программы и высоты блоков — десятичные строки (Rust U64). Суммы — десятичные строки u128. Подписывается SHA-256 от UTF-8 JSON-массива:

`["sealed-bounty/verdict/1", network, contract, bounty, hunter, submission, rules_hash, report_hash, valid, disclosure_hash, expires]`

Версия verdict должна быть `1`. Все элементы кроме `valid` — строки. Подпись Ed25519, публичный ключ и подпись в контрактном JSON представлены base64.

Commitment: SHA-256 канонического JSON `["sealed-bounty/report/1", context, nonce, attack]`. В объектах ключи сортируются; nonce — 32 случайных байта в lowercase hex. `submission` — отдельный случайный идентификатор длиной 32 байта в hex. Context содержит network, contract, bounty, hunter, submission. Подмена чужого commitment не даёт раскрыть его от своего hunter.

## Шифрование

Envelope: версия (1 байт), ephemeral X25519 public key (32), salt HKDF (32), IV GCM (12), tag (16), ciphertext. Ключ AES-256-GCM получен через HKDF-SHA256 от X25519 shared secret. AAD — канонический JSON context. Максимальный входящий envelope — 1 MiB; текст атаки — 64 KiB. Раскрытие шифруется на ключ команды с тем же контекстом и включает атаку и трассу. Хранилище принимает только ciphertext.

## Награда и заявки

Программа создаётся сразу с полной наградой; отдельного fund в v1 нет. Прилагаемый депозит точно равен reward + 0.01 NEAR. 0.01 NEAR — невозвратный бюджет хранения; он не входит в награду. На заявку прилагается 0.02 NEAR, также невозвратный бюджет хранения. Контракт проверяет фактический рост storage. Неиспользованный остаток бюджета остаётся в контракте.

Заявки принимаются до expires; общего on-chain лимита 256 больше нет. Побеждает первый валидный verdict, принятый on-chain, а не самая ранняя commitment. Это явный компромисс v1. Очередь ограничивает одновременно активные jobs (по умолчанию 64 на программу), а storage fee ограничивает расход on-chain; целевой спам всё ещё требует защиты.

Вся награда зарезервирована до settle_until. После этого спонсор может вернуть её, если победитель не назначен. Заявки, которые runner не успел проверить, после срока не оплачиваются; безусловная доступность runner не гарантируется.

Состояния: Available → Pending → Paid; при ошибке перевода Pending → Retryable → Pending. Только победитель может повторить выплату, адрес получателя закреплён. Возврат спонсору: Available → Refunding → Closed; ошибка возвращает Available. Пока перевод в пути, повтор запрещён. Невалидный verdict закрывает только свою заявку.

## Ограничения текущего блока

Есть файловая очередь, NEAR settlement adapter, CLI, базовая UI страница, тесты и старый testnet deployment. OutLayer WASI adapter собран, но живое TEE исполнение, проверка происхождения ключей в контракте, полная аттестация удалённой модели и browser wallet runtime не подтверждены. Обновлённый escrow контракт с запретом вывода `Retryable` пока не развёрнут. Типы и сборка не доказывают корректность security-механики; для нового состояния нужен новый deployment, миграция старого контракта не реализована.
